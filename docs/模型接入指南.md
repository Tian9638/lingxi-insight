# 模型接入指南 · 灵犀洞察完整版

> 适用对象：已克隆 `lingxi-insight`（Next.js 完整版）的开发者
> 目标：三步接入自有大模型 API，并理解其工作原理与注意事项

---

## 1. 原理：双通道架构

灵犀洞察的 AI 引擎是**可替换 Provider** 设计，两条通道共享同一套工具层：

```
用户提问
   │
   ▼
POST /api/chat ──► 读取环境变量 ──► 有 OPENAI_API_KEY ?
   │                                    │
   │                              否 ───┴─── 是
   ▼                                    ▼
本地演示引擎                      OpenAI 兼容通道（lib/ai/openai.ts）
（lib/ai/engine.ts）               · Chat Completions 流式请求
· ReAct 循环                       · Function Calling 工具循环
· 模板化洞察文本                   · LLM 生成洞察文本
                                   · 异常 → 自动回退本地引擎
   └────────────── 共用 tools.ts（query_data / forecast / rag ...）──────────────┘
```

**关键点**：无论走哪条通道，工具（数据查询、异常检测、预测、RAG 检索）都在
**服务端**对数据集真实执行；区别只在「洞察文本由模板合成还是由 LLM 生成」，
以及「工具由规则编排还是由 LLM 自主选择」。

## 2. 三步接入

### 第一步：创建环境变量文件

```bash
cd lingxi-insight
cp .env.example .env.local
```

### 第二步：填入三个变量

```bash
OPENAI_API_KEY=sk-你的密钥
OPENAI_BASE_URL=https://api.deepseek.com/v1
OPENAI_MODEL=deepseek-chat
```

### 第三步：重启服务（环境变量只在启动时读取）

```bash
npm run dev    # 或 npm run build && npm start
```

**验证生效**：提问后右侧「Agent 追踪」面板首行会显示 `模型就绪：<你的模型名>`；
运行统计区的 tokens 为 API 返回的精确值（非估算）。

### 附：在工作台内随时切换引擎

左侧「引擎设置 → 回答引擎」提供三档选择，无需改代码或重启：

| 选项 | 行为 |
| --- | --- |
| **自动**（默认） | 服务端配置了 Key 就用真实模型，否则用本地演示引擎 |
| **真实模型** | 强制走大模型；未配置 Key 时会明确提示原因并回退本地引擎 |
| **本地演示** | 强制本地引擎，不调用任何外部 API，完全离线 |

顶栏徽标会实时显示**最近一次回答的实际通道**（绿点 + 模型名 / 灰点 + 本地演示引擎）。
密钥始终只在服务端，前端仅传递偏好，不接触 Key。

## 4. 代码级说明（如需二次开发）

### 4.1 配置读取（lib/ai/openai.ts）

```ts
export function getOpenAIConfig(): OpenAIConfig | null {
  const apiKey = process.env.OPENAI_API_KEY;
  if (!apiKey) return null;               // 未配置 → 使用本地引擎
  return {
    apiKey,
    baseUrl: process.env.OPENAI_BASE_URL || "https://api.openai.com/v1",
    model: process.env.OPENAI_MODEL || "gpt-4o-mini",
  };
}
```

### 4.2 请求构造要点

- 端点：`POST {baseUrl}/chat/completions`，`Authorization: Bearer {key}`
- 工具：`tools: TOOL_DEFS`（OpenAI Function Calling 协议，定义见 `lib/ai/tools.ts`）
- 流式：`stream: true` + `stream_options.include_usage`（末帧返回精确 token 用量）
- 系统提示词：`buildSystemPrompt(input)` 注入数据集 Schema、工具规范与安全边界
  （见 `lib/ai/prompts.ts`）

### 4.3 工具循环

```
LLM 流式输出 → 累积 tool_calls → 服务端 executeTool() 真实执行
            → tool 消息回注 → 再次请求 LLM（上限 6 轮）→ 无工具调用则收尾
```

### 4.4 回退策略（app/api/chat/route.ts）

真实通道抛出 `error` 事件时，路由自动追加说明并切换到本地演示引擎，
保证评审演示不中断。回退时界面会明确提示，不会静默降级。

## 5. 安全与注意事项

| 事项 | 说明 |
| --- | --- |
| **密钥安全** | Key 只存在于服务端环境变量，永远不会发送到浏览器；`.env.local` 已在 `.gitignore` 中，切勿提交 |
| **必须支持工具调用** | 若模型不支持 Function Calling，LLM 将无法调用工具，只能做通用对话；请选择上表中支持 tools 的型号 |
| **费用** | 商用 API 按量计费，请在厂商控制台设置用量上限与告警 |
| **网络** | 服务端需能访问对应端点（国内厂商一般直连；OpenAI 需国际网络或代理） |
| **超时** | 长回答 + 多轮工具调用可能耗时 10-60 秒，属正常流式过程，请勿重复发送 |
| **Vercel 部署** | 在项目 Settings → Environment Variables 中配置三个变量即可，无需改代码 |
| **单文件版** | `standalone.html` 也可接入：点右上角「⚙️ 模型设置」填入 Key（仅存浏览器 localStorage，文件本身不含密钥），经 CORS 浏览器直连；适合不想装环境的场景，但不适合公共电脑 |

## 6. 故障排查

| 现象 | 原因与处理 |
| --- | --- |
| 追踪面板显示「模型就绪：灵犀-Pro」而非你的模型名 | 环境变量未生效：确认改的是 `.env.local`（不是 `.env.example`），且改后重启了服务 |
| 提示「真实模型通道暂时不可用，已回退本地引擎」 | 查看服务端终端的具体报错：401=Key 错误；404=BaseURL 或模型名错误；429=额度/限流；5xx=厂商故障 |
| LLM 不调用工具，只做通用回答 | 模型不支持 Function Calling，更换型号（如 `deepseek-chat`、`glm-4-plus`） |
|  tokens 显示为估算值 | 厂商不支持 `stream_options.include_usage`，代码已自动回退为字符估算 |
| 图表/表格不显示 | 工具未被执行——检查系统提示词中的 Schema 是否与数据集字段匹配 |
