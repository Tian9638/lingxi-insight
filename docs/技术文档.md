## 1 项目概述

### 1.1 背景与问题定义

数据分析是高校学生、中小企业运营人员与基层公务人员的常见需求，但传统路径存在明显门槛：
需要掌握 SQL 或 BI 工具、理解数据表结构、手工配置图表。与此同时，大语言模型与
Agent 技术在 2026 年已趋成熟，「用自然语言直接与数据对话」成为可能。

**本作品回答一个问题：能否让一个不懂技术的用户，在三句话内完成一次专业的数据分析？**

### 1.2 产品定位

灵犀洞察是一款 AI Native 的对话式数据分析平台。核心特征：

1. **AI 是核心而非附属**：意图理解、查询构造、图表选型、洞察生成全部由 AI 完成；
2. **过程透明**：Agent 的每一步规划、工具调用与执行结果对用户可见、可审计；
3. **结果可信**：所有数字来自服务端真实计算，预测类输出明确标注演示属性。

### 1.3 目标用户

- 高校学生（课程作业、科研数据处理、学情分析）；
- 中小企业运营、个体经营者（销售数据快速洞察）；
- 需要快速理解数据的教育、公共部门基层人员。

## 2 需求分析

### 2.1 用户故事

| 角色 | 场景 | 期望 |
| --- | --- | --- |
| 学生 | 拿到一份课程成绩 CSV | 上传后直接问「哪个学科挂科率最高」 |
| 运营 | 每日销售明细 | 「近30天销售额趋势」「各品类占比」一句话可得 |
| 管理者 | 季度复盘 | 一键生成结构化洞察报告并导出 |
| 研究者 | 上传文献资料 | 就文档内容提问并获得带引用的答案 |

### 2.2 功能需求

- FR1 数据接入：内置示例数据 + CSV 上传（自动类型推断）；
- FR2 自然语言查询：覆盖趋势、占比、排名、对比、相关性、异常、预测、报告八类意图；
- FR3 可视化：按数据形态自动推荐图表类型；
- FR4 可解释性：Agent 过程可视化；
- FR5 知识库：文档入库、切片、检索、带引用问答；
- FR6 多模态输入：语音转写；
- FR7 报告导出：Markdown 报告生成与下载；
- FR8 安全可控：输入护栏、生成中断、异常降级。

### 2.3 非功能需求

- 首屏加载 ≤ 200KB（工作台 121KB First Load JS）；
- 流式首包延迟 < 1s；
- 无后端数据库依赖即可完整运行；
- API Key 零硬编码；
- 响应式（桌面三栏 / 移动端抽屉）。

## 3 系统架构设计

### 3.1 总体架构

采用四层架构（详见 README 架构图）：

1. **用户界面层**：Next.js 14 App Router + React 18 + TypeScript + Tailwind CSS；
2. **交互协议层**：SSE 单向流 + 统一 `AgentEvent` 事件协议；
3. **AI 引擎层**：ReAct 编排 + 双通道（本地演示引擎 / OpenAI 兼容通道）+ 共用工具层；
4. **数据层**：内存数据集 + TF-IDF 倒排索引 + 统计算法。

### 3.2 关键设计决策

| 决策 | 选项 | 选择理由 |
| --- | --- | --- |
| 框架 | Next.js 14 vs Vite SPA | 竞赛推荐首选；需要 API Routes 承载 AI 服务端逻辑与 SSE |
| 流式协议 | 自研 SSE vs Vercel AI SDK | 自研事件协议结构更清晰、可完整展示「思考过程」；无 SDK 版本锁定，协议即文档 |
| 图表 | 自研 SVG vs Recharts | 零依赖、包体小；可精确实现预测虚线、异常标注等竞赛特色视觉 |
| AI 通道 | 仅真实 API vs 双通道 | 保证无 Key 环境下完整可评审；配置 Key 后无缝升级生产级 |
| 状态管理 | Zustand vs Redux | 轻量、无样板代码、TS 友好 |

### 3.3 数据模型

- `DatasetPayload`：columns（名称 + 类型）+ rows（ Record<string, string|number> ）；
- `AgentEvent`：10 种事件的判别式联合（详见 `lib/types.ts`）；
- `ChatMessage`：内容块列表（text / metrics / chart / table / citations / report / error）。

## 4 AI 技术方案

### 4.1 意图理解（规则 + 同义词映射）

`classifyIntent` 基于优先级关键词匹配识别 10 类意图；
`parseQuery` 将问题解析为结构化 `QuerySpec`：指标（列名 + 同义词）、维度、
聚合方式、时间范围（最近 N 天 / 本周 / 上月 / N 年）、时间粒度（日/周/月）、
Top N、维度值过滤（含前缀模糊匹配）。解析失败时进入「澄清引导」而非猜测。

### 4.2 数据查询引擎

`queryData` 执行：行过滤（时间范围 + 维度值）→ 分组（时间分桶 / 类别）→
聚合（sum/avg/max/min/count）→ 排序 → Top N 截断，输出图表序列、表格、
指标卡与统计量（总计、均值、峰谷、环比变化）。上一周期对比通过日期平移窗口真实计算。

### 4.3 Agent 编排（ReAct）

规划 → 工具调用 → 观察 → 生成。深度思考模式追加「数据质量检查」与「交叉验证」步骤；
异常/预测/相关性意图追加对应专用工具。全过程以事件流输出，前端实时渲染。

### 4.4 工具集（Function Calling）

| 工具 | 算法 | 输出 |
| --- | --- | --- |
| query_data | 分组聚合 | 序列 + 表格 + 指标卡 |
| recommend_chart | 数据形态 → 图表类型 | ChartSpec |
| detect_anomaly | Z-Score（阈值 1.8） | 异常点 + 标注序列 |
| forecast | 最小二乘线性回归 | 预测虚线序列 |
| analyze_correlation | Pearson r | 散点 + 相关系数 |
| search_knowledge | TF-IDF 余弦 | 引用列表 |

### 4.5 RAG 知识库

切片（160/40 滑动窗口，标点优先）→ 分词（中文二元组 + 英文词）→ TF-IDF →
余弦相似度 Top-3 → 抽取最相关句子作为引用。相关度阈值 0.08，未命中即回退数据分析通道。
接口与 Embedding 检索对齐，可平替向量数据库。

### 4.6 真实模型接入

配置 `OPENAI_API_KEY` 后切换至 OpenAI 兼容通道：系统提示词注入数据 Schema 与工具规范，
流式接收 LLM 输出，累积 tool_calls 后本地执行并回注，循环直至无工具调用（上限 6 轮）。
异常时自动降级本地引擎，保证评审演示不中断。

### 4.7 Prompt 设计要点

角色约束（数据分析助手）、Schema 注入（字段名与类型）、工具使用规范
（指标维度必须真实存在、口语映射、禁止编造数字）、输出结构（结论→依据→建议）、
预测免责声明、安全边界。

## 5 核心功能实现

### 5.1 流式渲染管线

`fetch` → `ReadableStream` reader → 按 `\n\n` 切分 SSE 帧 → JSON 解析 → 事件分发：
`text` 增量追加至末尾文本块（配合打字光标），`tool_result` 推送图表/指标/表格内容块，
`tool_call/result` 更新追踪面板（含真实耗时）。`AbortController` 支持随时中断。

### 5.2 纯 SVG 图表引擎

- 折线：`pathLength=1` + dashoffset 实现描线入场动画；面积渐变；预测序列虚线；
  异常点脉冲圆环；`<title>` 原生 tooltip；
- 环形：极坐标弧路径 + 中心汇总值 + 图例百分比；
- 条形/水平条形：`transform-box: fill-box` 实现生长动画；
- 散点：双轴 nice-scale 刻度；
- 「好看」的刻度算法：基于数量级的 step 取整（1/2/5×10^n）。

### 5.3 CSV 上传与类型推断

PapaParse 解析 → 每列抽样 50 值 → 全数值 / 全日期 / 文本三态推断 →
值强转（数字 parseFloat、日期归一化 YYYY-MM-DD）→ 上限 5000 行防护。

### 5.4 报告生成

`composeReport` 汇总：数据概览（行列数、时间范围、维度基数、指标统计表）、
核心发现（整体表现、峰谷、结构集中度、指标相关性）、月度趋势、行动建议、
会话问题回顾；以 Markdown 流式输出，前端轻量渲染并支持下载。

### 5.5 响应式与可访问性

桌面三栏（数据源 288px / 对话自适应 / 追踪 320px）；移动端侧栏抽屉、右栏 Tab 隐藏；
`prefers-reduced-motion` 降级所有动画；语义化标题与 aria-label。

## 6 测试与部署

### 6.1 测试

- **类型安全**：`tsc --noEmit` strict 模式零错误；
- **端到端测试**（`scripts/e2e-test.mjs`，13 项断言全部通过）：
  趋势/占比/排名/对比/预测/异常/相关性/报告/问候/护栏十条对话路径 +
  RAG 引用 + `/api/rag` 检索接口 + `/api/report` 报告接口；
- **构建验证**：`next build` 通过，6 路由，工作台 First Load JS 121KB；
- **真实计算校验**：所有断言中的数字均由查询引擎现场计算，测试数据为种子生成可复现。

### 6.2 部署

标准 Next.js 应用，支持 Vercel / Node 服务器 / Docker 部署：

```bash
npm install && npm run build && npm start   # 默认 3000 端口
```

无外部服务依赖（数据库/对象存储均不需要）；SSE 已禁用代理缓冲
（`X-Accel-Buffering: no`）。

## 7 总结与展望

### 7.1 总结

本作品以「AI 过程透明化」为核心设计理念，构建了完整的 AI Native 数据分析应用：
统一事件协议实现前后端解耦，双通道 AI 引擎兼顾可评审性与生产级能力，
自研 SVG 图表引擎实现零依赖的可视化，RAG 与安全护栏完善了 AI 应用的可靠性。
13 项端到端测试全部通过，全部统计数字真实可复现。

### 7.2 不足

- 本地引擎的解读文本为模板化合成，个性化程度依赖真实模型；
- 预测为线性外推，未建模季节性；
- 数据集未持久化，刷新后恢复初始状态。

### 7.3 展望

接入向量数据库实现语义级 RAG；引入季节性预测模型；扩展多 Agent 协作
（分析/图表/报告 Agent）；增加数据持久化与团队协作看板。
